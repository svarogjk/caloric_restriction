# F01 — Remove Mock KM Data

**Size**: S | **Priority**: 1 (highest — scientific credibility risk)

## Problem

`KaplanMeierPlot.tsx` generates a synthetic smooth curve from `avg_hazard_ratio` alone when real KM data is unavailable, and displays it identically to real KM data. Experienced bioinformaticians will catch this and it destroys trust in all results.

## Files to Read First

- `frontend/src/components/KaplanMeierPlot.tsx` (full file)

## Implementation

1. Find the `mockKMData` `useMemo` block (generates fake time/survival arrays from avg_hazard_ratio). Delete it entirely.
2. Find every `|| mockKMData` or `?? mockKMData` fallback. Delete those too.
3. Find the no-data branch (currently hidden because mock fills in). Replace it:

```tsx
// Render this when allKmChartData is null or empty:
<div className="flex flex-col items-center justify-center h-64 text-center p-6 bg-gray-50 rounded-lg border border-gray-200">
  <div className="text-gray-500 text-sm font-medium mb-2">
    Kaplan-Meier curve data unavailable
  </div>
  <div className="text-gray-400 text-xs max-w-md leading-relaxed">
    KM curve data requires time-to-event columns to be present and extractable
    from each dataset's sample metadata. The hazard ratio and p-value shown above
    are valid — they come from Cox proportional hazards regression on expression
    quartiles.
  </div>
</div>
```

4. Keep the per-dataset stats table (HR, CI, p-value, N) visible even when no KM curve data is available.

## Verification

```bash
cd frontend && npx tsc --noEmit && npm run build
```

Manual test:
- Run an analysis → open KM modal for any gene
- Confirm: either real KM curves OR the informational "unavailable" panel renders (never a synthetic curve)
- Run an analysis that definitely has KM data → confirm real curves still render correctly with CI data
